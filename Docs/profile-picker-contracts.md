# API13 picker, aliases and public profile increment

This is a local implementation on main at 31fdd5a9d9a9bf19d6268c24504496bb54b75e2a. Existing privacy defaults remain NO_ONE and no stored profile policy is changed by this migration. No real account data has been published. FILE03 stays partial; its journal/fence work is preserved separately.

## Shipping contracts

All routes below are under the application /api/v1 prefix.

- GET /users/me/audience-picker?field=BIO&q=...&limit=30&cursor=... searches workspaces and individual accounts together in one parameterized server query. field is required (any ProfileAudienceField), q is a literal substring up to 120 characters, limit is 1..100, and cursor is an opaque keyset continuation. Public account names and username, plus only the caller's contact alias, match. A leading @ matches username; search never scans other owners' aliases. Multiple matching identity/alias branches deduplicate account IDs. Empty/whitespace q and a lone @ browse only the caller's workspace; outside OPEN accounts are discoverable through a nonempty search.
- Add workspaceId to expand the caller's current workspace into account children. The owner explicitly selected own-workspace browsing plus outside-account search on 11 October (Sentinel_879fe29777788191aebdfc75c9253902). Foreign workspace labels and rosters are not discoverable. The authorized parent label is the existing Workspace.slug; no separate name is invented. Foreign expansion and unknown workspace IDs return the same 404, including for administrators. Global individual public-name search is supported independently, with no foreign workspace affiliation disclosed.
- GET/PUT/DELETE /users/me/contacts/:accountId/alias reads, sets or clears an owner-private alias on an existing Contact. PUT requires {alias: string|null}; nonblank plain text up to 120 characters is trimmed, null clears, omission is invalid. DELETE clears without removing the Contact. A missing Contact returns 404 instead of implicitly creating an audience grant. Owner identity comes only from authenticated server state. Alias changes never rename the actual account, reciprocate contacts, modify policies, or notify anyone. Existing Contact remove deletes its alias. Actual account identity stays separately visible and unambiguous.
- GET /profiles/:accountId and GET /profiles/by-username/:username return public identity plus viewer-visible biography and independent birthday day/month/year. Username normalization matches existing registration behavior; an optional leading @ is accepted. Names/usernames are explicitly public by the user's decision. displayName composes existing independent names or preserves the untouched legacy fullName; it never splits legacy text. Only available OPEN accounts resolve; inactive and missing accounts return the same 404 without exposing lifecycle state.

Picker and alias routes require only a current authenticated OPEN account; they do not add admin, project or roster permissions. Public reads allow anonymous requests; if Authorization is supplied, invalid/malformed/inactive credentials return 401 rather than silently falling back to anonymous. The optional guard and audience projection load current persisted viewer identity and membership, ignoring stale token workspace claims or client-supplied viewer parameters. Every response has Cache-Control: no-store. A policy/read failure returns 503 rather than a permissive fallback.

Public identity fields are id, displayName, firstName, lastName and username. Public profile adds bio, birthdayDayMonth {day,month}|null and birthdayYear|nullable number. Hidden and unset parts both use null. There is no alias, phone, password, role/permission, contact list, workspace ID/detail, full birthDate, lifecycle or Telegram field. Avatar/status data/delivery are still unimplemented and are not pretended to be public fields. Private self reads remain separate; even the owner viewing the public route follows field audiences.

Audience semantics remain: Everyone includes anonymous viewers; Contacts is unilateral owner->viewer; Custom unions explicit account entries with current selected-workspace membership; birthday parts are independent; absent policy is private. Explicit account grants survive workspace changes. No real account audience default or stored grant is broadened.

## Rendering, pagination and saved selections

items is a typed WORKSPACE/ACCOUNT union with stable IDs; clients use kind+id to identify a row. Account results include actual public identity, caller-owned alias, isContact, explicitSelected, parentWorkspaceId and selectedViaWorkspace. Parent affiliation and workspace-derived selection are available only within the authorized current tree; both are null for a foreign account, because returning even a membership-based selection bit could infer an unauthorized roster. Null means unknown, not false.

workspaceContext is the authorized current parent, retained on child and filtered pages. Its explicitSelected denotes the saved dynamic workspace grant. CHECKED means that parent grant; INDETERMINATE means saved explicit account grants include at least one currently OPEN child; UNCHECKED means neither. The calculation ignores search/page filtering. Explicit child sets, even all current children, do not become a dynamic workspace grant or predict future membership. No total member/viewer count is fabricated.

selection is the complete saved field policy with accountIds/workspaceIds and selected-entry counts. It retains every saved off-page or unavailable/foreign selection, without loading unauthorized labels/rosters. Changes continue through the existing complete-set audience Save/replace endpoints; picker reads never mutate selection. When policy is not CUSTOM, arrays remain empty as in the existing privacy response.

Rows sort by kind then stable ID, with a limit+1 lookahead and a nextCursor or null. The cursor is validated against caller, current workspace, field, exact trimmed query and expansion scope; it cannot expand authorization. Invalid or mismatched cursors return 400. This is live keyset pagination, not a frozen multi-request snapshot: membership/data changes are reflected on new reads, newly inserted lower keys may need a fresh search, and caller workspace changes invalidate continuation. Complete saved selection sets are reloaded independently of page contents within each RepeatableRead transaction.

## Migration and deployment requirements

20261011060000_profile_picker_alias adds nullable ProfileContact.alias VARCHAR(120), no backfill, plus five lower-case trigram GIN indexes for OPEN account full/first/last names and username, and contact aliases. The existing contact owner/key indexes limit private alias eligibility. Search uses a UNION of matching public account IDs and owner-scoped alias target IDs before projection, with escaped literal LIKE patterns and bound Prisma.sql parameters.

pg_trgm must be available and the authorized migrator must have extension creation privileges, or a database operator must provision that extension before deployment. Regular GIN index creation takes schema/write locks and may be expensive on large tables; use a deliberate migration window and verify plan/size on production-equivalent data. The statements are not wrapped in a transaction; a partial DDL failure must be inspected rather than blindly rerun. Raw expression/partial indexes are maintained by this SQL migration rather than Prisma model annotations. Only the isolated localhost:55439/profile_test database received this migration; no production deployment, migration or publication happened. Existing aliases all begin null.
