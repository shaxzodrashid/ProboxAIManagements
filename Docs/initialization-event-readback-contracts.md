# MAIN03 initialization event continuity and current authorization

Local implementation, 12 October 2026. This closes the initialization replay-to-live handoff and opening-only authorization gaps within MAIN03. It does not complete Home composition, shared snapshot aggregation, Task Manager, initialization worker containment or any other unchecked portion.

## Existing routes, revised delivery

`GET /api/v1/projects/:projectId/initializations/:initializationId/events?after=0&limit=100` returns the existing JSON array of `{id,initializationId,sequence,type,payload,createdAt}`. Project/initialization IDs must be UUIDv4. after is an exclusive integer initialization sequence from 0 to 2,147,483,647; limit is 1–100, default 100. Cache-Control is no-store. Events are read in ascending contiguous sequence from a consistent high-water boundary.

The new page bound is an intentional compatibility change: callers formerly receiving an unbounded array must request another page after the last returned sequence. A full page may have more; a shorter page reaches that read's boundary, not a permanent terminal state. Concurrent later commits appear in subsequent reads. No all-time count or cross-resource snapshot is promised. Repository inspection found no internal caller using this REST route; external clients must adopt paging.

`GET /api/v1/projects/:projectId/initializations/:initializationId/events/stream` uses SSE. Supply after or Last-Event-ID; both must agree if present. Last-Event-ID is a canonical nonnegative decimal integer within the same bound. limit is REST-only and rejected on SSE. Each event keeps `{id:sequence as string,type,data:payload}`. The matching REST payload and SSE data are identical; payload disclosure is unchanged. These are initialization events, not the session event envelope.

The endpoint validates a one-event probe before opening SSE, then starts fresh persisted reads on subscription. It does not switch from replay to an in-process Subject. Commits between the probe and subscription, commits from another process and missed publish notifications remain retrievable. Stream batches contain at most 100 events, drain full pages promptly and otherwise poll every 500 ms. Clients persist their processed cursor and deduplicate by `(initializationId,sequence)` on reconnect; transport receipt does not prove durable client processing. A cancelled or terminal attempt retains readable history, without automatically starting another attempt or stopping the subscription before token expiry.

## Current authorization and failure boundaries

Each REST page and SSE batch checks current OPEN account, unchanged workspace, projects.initializations.read and existing project read scope in the same RepeatableRead transaction as the initialization high-water and events. Existing project scope remains membership, current projects.read-all or readAccessEnabled. projects.manage-all alone is not a read bypass. The captured actor permission array cannot preserve a revoked grant.

Foreign/missing projects or mismatched initialization/project identities remain 404. Current account/grant or project-scope loss is 403 in an established stream; ordinary requests still pass the existing authentication guards and may return 401/403 before the readback. Authorization is evaluated at each batch's consistent snapshot: a concurrent revocation after that snapshot does not retract already authorized/delivered data, but subsequent batches re-evaluate it. This is not instantaneous revocation of previously received client data.

Stream closes at access-token expiry, on authorization/resource loss or delivery failure. Expiry is checked before/after database reads and before each emission; expiry during an in-flight read prevents its later delivery. Missing expiry means immediate completion rather than an indefinite stream. Unsubscribe clears polling and suppresses the result of an in-flight database read. It does not cancel the initialization worker, database transaction or subprocesses. Existing explicit setup-cancellation behavior is outside this batch.

Malformed cursor/limit/header/UUID is 400. A cursor ahead of persisted history is 409. Missing middle or trailing sequences below the high-water return 409 INITIALIZATION_HISTORY_UNAVAILABLE, never an empty successful page; reconcile initialization state and report unavailable history instead of skipping the hole. Database failure becomes sanitized 503 INITIALIZATION_EVENT_DELIVERY_UNAVAILABLE. Stream errors after headers close delivery; clients use authenticated REST reconciliation, without assuming an HTTP status can be sent after SSE has opened.

The stored type/payload/log contract is preserved. This batch adds no redaction policy, retention/pruning rule, permission key, account grant, external integration, task association or automatic retry/worker action. The existing in-process event publisher remains for compatibility; endpoint correctness no longer depends on it.
