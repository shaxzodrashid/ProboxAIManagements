# FILE03 writer and runner facts

Read-only follow-up; no new writer policy, storage model or enforcement is implemented.

- API filesystem mutations include folder creation, upload/move, file trash/restore, expiry cleanup and project purge in src/projects/projects.service.ts. Project initialization materializes trees and executes manifest commands in src/projects/project-initialization.service.ts. Codex sessions are another writer; arbitrary user shells/editors remain outside this application's process registry.
- ProboxAiRunner.run waits for its tracked child's close and stream consumption during normal completion. interrupt(sessionId) sends SIGINT to that child and immediately returns a boolean; it does not await closure or enumerate/reap descendants (src/sessions/proboxai-runner.service.ts:67,94). The configured proboxai launcher itself spawns Codex in bin/proboxai.mjs, so signalling the launcher is not proof of Codex or tool-child termination.
- Initialization commands use detached Linux groups; terminateProcess sends group SIGTERM where available. The timeout rejects immediately after requesting termination, before a close event proves completion (src/projects/project-initialization.service.ts:537,557,816). This is stronger targeting than the session runner, but still not confirmed containment/reaping.
- The session CAS permits one active turn per session, not one writer per project (src/sessions/sessions.service.ts:69). Multiple session cwd values may share a project. activeProjectSessions checks queued/running/paused sessions whose cwd lies inside the project, scoped to its workspace (src/projects/projects.service.ts:1172). It cannot discover an overlapping writer launched from an ancestor or a separate arbitrary shell. File delete currently does not invoke this project-purge check.

A temporary reject-delete-while-known-sessions-active guard is implementable as a narrower busy policy, but alone is racy with session starts and says nothing about arbitrary shells or escaped descendants. A real managed-writer exclusion contract must serialize all API writes and session/initialization starts by project, contain subprocess trees, wait for confirmed closure/reaping and retain uncertain executor fences. Independent shell writers need an enforced namespace/access contract too. These changes alter deployment/runner policy; no such policy is assumed or implemented in the current FILE03 partial batch.

Recommended option communicated by the parent is per-project enforced writer exclusion for delete/restore, returning busy whenever quiescence cannot be proved, with versioned/snapshot recovery considered later. Best-effort quarantine plus manual reconciliation remains the current limited option. This document does not authorize that recommendation. Native no-overwrite rename alone never proves source identity against uncoordinated name replacement; existing open descriptors can also mutate moved content. Preserve these limitations when describing FILE03.
