# SESSION01/03 durability and SESSION05 recovery foundations

The recovery policy below remains the legacy-row contract. Later approved
[initial intent/history](session-intent-history-contracts.md) and
[20 October REST follow-up recovery](rest-followup-recovery-contracts.md)
supersede it for explicitly supported never-started work. Started/ambiguous runs
remain blocked; migration does not opt historical pending turns into dispatch.

Local, uncommitted implementation in the existing ProboxAI checkout. Prior batches remain preserved. No live AI runner, external spending, deployment, push or production migration was performed.

## Persisted history and SSE

GET /api/v1/sessions/:id/events accepts after (exclusive sequence, default 0), limit (1..100, default 100), and optional untilSequence. The first response captures its session snapshot and highWaterSequence in one PostgreSQL repeatable-read transaction. It returns session, ordered events, after, nextCursor, highWaterSequence, hasMore and historyAvailability=RETAINED_WITH_EXPLICIT_OMISSIONS. For bounded pagination, retain the first highWaterSequence and pass it as untilSequence on subsequent requests. The session snapshot is current to each request and its lastSequence may exceed that fixed historical boundary. An ahead or inconsistent cursor is 409. Missing persisted sequences are explicit 409 SESSION_HISTORY_UNAVAILABLE, never an empty successful page or an endless catch-up loop. No retention expiry or pruning policy is introduced; deletion of a whole session remains 404.

Each event has stable database id, sessionId, nullable turnId, sequence, type, createdAt, source SERVER/RUNNER, legacyProjection and data. Viewers are not represented as event authors. Sequence and hash predecessor allocation occur while holding the session row lock. New writers persist only projectionVersion=1 allowlisted data; historical rows remain version 0 and are safely projected on read without rewriting their stored raw evidence or claiming equivalent historical availability.

Assistant messages retain at most 16,384 JavaScript characters with a truncated marker. Item IDs must satisfy a bounded identifier grammar. Tool events retain only item id/type/status, with TOOL_DETAILS_EXCLUDED markers. Commands, arguments, stdout/stderr, structured file paths, raw provider errors, hidden reasoning and unsupported event payloads are excluded. Unsupported events preserve their sequence with an omission marker. Runner lifecycle frames are explicitly non-authoritative. Known environment secret values are replaced in assistant content, but this is best-effort: permitted assistant text may itself include secrets, paths or personal content. There is no claim of exhaustive content redaction. Raw runner archives retain their existing server-side storage policy and are not exposed by these endpoints.

GET /api/v1/sessions/:id/events/stream reads the same persisted history repeatedly rather than joining a transient live channel. It accepts after or Last-Event-ID; if both are supplied they must agree. Fixed untilSequence is unsupported on SSE. Pages are serialized, emitted with sequence as SSE id and the persisted envelope as data, and followed by another database read after the last emitted sequence. There is no history-to-live handoff gap. Polling is 500ms after an exhausted page, immediate while catching up. A client retains the last processed sequence, reconnects after it, and deduplicates by sequence; transport delivery is not an exactly-once acknowledgment protocol. Reconnect and REST pagination recover committed events. Sensitive current account state, workspace, assigned manager and sessions.read grant are rechecked for each batch. The stream closes at token expiry, or errors on authorization/history loss. Unknown persistence errors are sanitized to a delivery-unavailable response. No sensitive payload is published through the former actor-augmented raw REST SSE channel.

## Authoritative committed state

Acceptance, execution claim, terminal success/failure/interruption, authorization loss before claim and orphan reconciliation append SERVER session.state in the same transaction as their associated state changes. Session/turn IDs are envelope fields; authoritative payloads contain sessionStatus, turnStatus, stopConfirmation and recoveryReason. An early runner turn.completed cannot establish committed completion. State-event insertion failure rolls the state transaction back; an expired lease subsequently exposes recovery rather than asserting a success that was not committed. GET session and turns now share a coherent repeatable-read snapshot.

Task/session locking serializes task aggregation. Any QUEUED/RUNNING session keeps the task RUNNING. With no active sessions, the newest-created session (createdAt then id) determines COMPLETED/FAILED, otherwise CANCELLED. This is a bounded implementation rule, not an all-session liveness API; PAUSED/ARCHIVED handling remains conservative and may require a later product policy. One older completion cannot overwrite another active or newer session's task state.

## Ownership, interruption and recovery

A process-instance UUID owns each accepted run. Database-clock leases last 60 seconds and are renewed every 10 seconds only while unexpired and the target turn remains RUNNING. Claims, events, usage and terminal commits validate owner, target turn and lease. Runner control and stop observations additionally bind to turnId, so an old heartbeat cannot signal a replacement child. Current actor/account/workspace/manager/grant are checked before execution claim and again immediately before actual spawn. No lease is resurrected after expiry.

POST /api/v1/sessions/:id/interrupt now requires {turnId: UUIDv4}. This deliberate target prevents a repeated old request from signaling newer work. The durable intent and SERVER session.interruption event commit before any signal. A queued target becomes INTERRUPTED with NOT_STARTED, preventing launch. For a running target, signal acceptance is persisted separately. Repeated requests for that target return the recorded outcome; after a replacement turn, an old target is 409. The response contains interrupted (signal accepted), turnId, stopConfirmation, requestedAt and nullable signalAcceptedAt. interrupted=true never proves termination. The owner consumes pending intent at the pre-spawn boundary and during heartbeat renewal, including intent received by another HTTP process. Unknown commit acknowledgments return 503 and require readback/reconciliation rather than submitting a new target.

Project-owner deletion INTERRUPT decisions use the same durable target primitive and freshly recheck OPEN account, projects.delete, project ownership, pending deletion request, workspace and directory containment. They do not impose assigned-manager sessions.manage. Telegram /stop supplies the observed turn ID. All these paths preserve existing FILE03 limitations: process-group containment and external filesystem writers are not proven safe by local runner exit.

Session service startup and a 10-second worker reconcile at most 100 expired/legacy-active sessions per pass, with locks and a fresh database-clock check. Another healthy owner is preserved. All historical active turns are settled together, with attributable state events; Telegram's unconditional startup rewrite is removed. Prompts and output remain persisted. Queued never-claimed work can be recovered with NOT_STARTED and then receive a new deliberate submission; retrying its existing accepted request never relaunches it. A claimed or legacy lost run becomes INTERRUPTED/OWNER_LOST/STOP_UNCONFIRMED. No prompt is automatically replayed.

Stop evidence distinguishes NOT_OBSERVED (historical default), NOT_STARTED, STOP_UNCONFIRMED and LOCAL_EXIT_OBSERVED. A spawn rejection or successful kill request does not prove close. The runner retains an unclosed child in its map; only the observed close event establishes local exit. Descendants may remain. Recovery does not overwrite stop uncertainty with a false exit observation from a stale executor.

SESSION05 remains partial: new follow-ups are blocked while STOP_UNCONFIRMED. An owner/manager acknowledgment or trusted operator reconciliation policy, its permission and audit contract have not been approved, and no override endpoint is invented. This exposes an honest interrupted recovery state, but is not a complete interactive recovery path for an unknown surviving process.

## Migration and rollout

20261011080000_session_durability adds nullable ownership/lease/recovery/interruption timestamps, a NOT_OBSERVED stop-evidence default, version-0 historical event projection, nullable turn executionPermission and a lease lookup index. 20261011090000_session_interrupt_target adds nullable interruptTurnId. These are additive, preserve legacy prompts/raw rows and do not backfill old raw events as safe version 1. Both were applied only to the verified localhost:55439/profile_test isolated database. Old active runs are treated conservatively as unconfirmed on recovery.

Rollout must quiesce old session writers/executors and coordinate clients for required turnId, richer interrupt responses, new event envelopes and cursor semantics. Old binaries can bypass leases and still write raw events. Do not enable new recovery against simultaneously running old unleased executors. No production migration or rollout is authorized by this local implementation.
